概要 (Overview)

morse-app

「災害時等、ネットワークから隔絶された状況でも利用出来るシンプルなモールス信号の送受信システム」...を目指している

GitHub Pagesのページ：

https://numberzero-0621.github.io/morse-app/

説明

このウェブアプリは、大規模な災害によってインターネット接続が不可能になった時や、山間部などのそもそも回線が通っていない圏外の地域において、ネットワークから隔絶された状況でもマイクやスピーカーといったデバイスに元々付属している機能だけを用いてローカルに動作させることで、擬似的に近・中距離（20m～100m程度）でのテキストメッセージのやり取りを可能にすることを主な目的としたものです。

普段私達が会話に用いている言語とは異なり、モールス信号は「トン」と「ツー」と「（無音）」の3種類の情報しか扱わないため、騒音の激しい環境や言語の届きにくい状況でも比較的安定してテキストの送受信が行えるのではないかと思い、開発に至りました。

「オフラインでも動作させたいのになんでウェブアプリなの？」という質問に対しては、そのほうが開発が遥かに容易だったから仕方なく、とお答えしておきます。
なるべく静的に動作するように設計しているので、一度キャッシュとしてファイルを読み込んでしまえば音声認識等の一部のAPIを必要とする機能以外ならオフラインでも問題なく動作するはずです。

イメージとしては、2人がちょっと離れたところからそれぞれスマホを使ってピーピー音を鳴らしてテキストを送受信する使い方です。
お互いに使用する周波数などを事前に示し合わせておいたほうがいいかもしれません。

開発を通して

本当は光を介してもモールス信号の受信を行いたかったのですが、受信側のカメラ認識等の設定が困難であることから断念し、受信は音声に絞りました。
また、実際に送受信のテストを行ったところ、原文が正確に復元されたパターンは非常に少なく、文字がおかしくなったり認識されなかったりすることが多かったです。両者のデバイスのパラメータを細かく調整し、最適な環境を整え、やっと正確に送受信が行えました。
また、受信の際の音量の「しきい値」の設定も難しかったです。送信するデバイスの設定している音量やデバイス間の距離、周囲の雑音などを考慮する必要があり、一発で送受信を成功させるのはとても難しいと感じました。
しきい値の自動調節機能もまだ設計が甘く、しきい値が過度に低くなり過ぎて、音が一旦鳴り終わった後も、しきい値を下回れずに次の音が鳴ってしまい、正確に信号が捉えられなかったです。
文字起こしのように、AIによって前後の文脈を捉えそこから推測して信号を補完する機能をつければなんとかなるのかもしれませんが、それなら現時点では人間がモールス信号を覚えてペンと紙を用意して解読したほうが手っ取り早いように感じました。

総じて、災害時や山間部等、ネットワークから隔絶された状況における遠距離メッセージ送受信システムとしては、実用性はかなり低い、と言わざるを得ない結果となりました。
また、もちろんこのようなモールス信号の暗号化・復号を行えるサイトは無数にあり、そのうちのいくつかは参考にさせていただきましたが、明確な差別化などが行えなかったこともやや心残りではあります。

今後の展望

そもそも学校の課題で試しに作っただけなので、あまり今後これをどうこうしていきたい、とかは無いのですが、なるべく正確にモールス信号の送受信が可能になるように調整はしたいかもしれませんね。
もしこのリポジトリに興味を持ってくださったり、自分で更に開発したい、という方がいらっしゃいましたら大歓迎です！是非ともご活用ください～
